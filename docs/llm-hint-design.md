# 適応型ヒントとLLM設計

## 目的

LLMは正誤判定を行わず、LocalJudgeの決定的な結果と学習者の質問を材料に、
次に考える一歩だけを提示します。完成コードを生成するチャットではなく、
既存の段階的ヒントを個別化するための交換可能なアダプタとして扱います。
問題完了後に限り、同じアダプタ境界で提出コードの改善レビューも生成します。

## 信頼境界

LLMへ渡してよい情報は、学習者へ既に公開されている問題情報、現在のコード、
学習者が入力した質問、安全化済みのJudge診断、直近の会話履歴です。
クラウドプロバイダへ送る前には、ブラウザセッションごとの明示的な同意を必要とします。

次の情報はプロバイダへ渡しません。

- 隠しテストの入力、期待出力、ケースID、件数以外の内部情報
- 模範解答と教師モード専用データ
- 生のstderrとJudge内部例外
- プロフィール表示名
- APIキーなどの秘密情報

同意はプロフィール設定へ保存しません。保存済みのモデル設定を、将来のクラウド送信に
対する許可として扱わないためです。

完了後のコード改善レビューには、上記に加えて学習者へ公開済みの解説と、
完了理由（全テストACまたはギブアップ）を渡します。固定小テストの正解・解説、
模範解答、隠しテスト、Judge内部結果は渡しません。プロフィールIDはSHA-256で不可逆な
学習者キーへ変換し、表示名は送りません。

## プロバイダ

| UI表示 | 内部ID | 既定モデル | 接続方式 |
|---|---|---|---|
| GPT-5.6 | `openai` | `gpt-5.6-sol` | OpenAI Responses API |
| Gemma 4 12B | `gemma` | `google/gemma-4-12B-it` | 外部vLLM／llama.cpp互換API、または専用Transformers HTTP API |
| Gemini | `gemini` | `gemini-3.6-flash` | Google Gen AI SDK |

モデルIDとGemmaの接続先は環境変数で上書きできます。プロバイダ実装は遅延初期化し、
キーや外部サーバーがない状態でもアプリを起動できるようにします。

Gemmaはアプリと同じプロセスや標準Composeサービスへ組み込みません。12Bモデルの
メモリ要件を、512MBに制限したWebアプリと分離する意図です。vLLMが利用できない
ホストでは、FastAPIが構造化JSONを担当し、Transformersモデルはプレーンテキストの
ヒントだけを生成する専用サーバーを使います。詳細は
[Gemmaサーバー導入・運用ガイド](gemma-server.md)を参照してください。

## ヒント生成フロー

```text
質問 / 「わからない」
  -> TutorService
    -> 公開情報だけからHintGenerationRequestを構築
    -> プロフィール設定に応じてHintProviderを選択
    -> プロバイダ固有APIを呼び出し
    -> 共通スキーマへ変換
    -> HintSafetyPolicyで答え漏洩を検査
    -> 会話履歴を保存してUIへ返す
```

キー不足、接続失敗、タイムアウト、不正な構造化出力、答え漏洩検査失敗では、
別のクラウドプロバイダへ自動転送しません。既存のRuleBasedヒントへ退避し、
学習を継続できるようにします。

プロバイダ障害は、認証・権限、モデル不明、利用上限、タイムアウト、一時障害、
空またはブロック応答、構造化出力不正などの秘密情報を含まない原因コードへ分類します。
UIとproductionログはこのコードだけを利用し、SDKの生例外本文や応答本文を渡しません。
developmentでは、原因分類前の例外を失わず調査できるよう、認証情報を伏字化した例外本文と
スタックトレースを端末ログへ出します。Geminiのdoctor診断はモデル情報取得だけを行い、
学習者コンテキストを送信しません。

GeminiアダプタはAPIキー方式のDeveloper APIを明示的に選択します。Vertex AI／Enterpriseの
環境設定を暗黙に利用しないことで、認証方式、課金境界、データ送信先が起動環境によって
変わることを防ぎます。

## コード改善レビュー生成フロー

```text
全テストACまたは初回ギブアップ
  -> CompletionReviewServiceがProblemProgressを再確認
  -> 16KiB以下の現在コードと公開済み教材だけで要求を構築
  -> 外部送信ならブラウザセッション同意を確認
  -> 選択中プロバイダへ厳密な構造化出力を要求
  -> 共通GeneratedCodeReviewへ検証・変換
  -> HintSafetyPolicyとコード行再掲検査
  -> 合格したレビュー文だけをSQLiteへ保存・表示
```

出力はアルゴリズム要約、最大3件の良い点、1〜5件の優先改善点です。改善点の分類は
`correctness`、`edge_cases`、`complexity`、`readability`、`maintainability` に限定します。
置換用ソース、コードブロック、完全解答、隠しテストへの言及を指示で禁止します。
さらに、提出コード中の12文字以上の行が応答へそのまま含まれる場合は、保存・表示せず
安全な再試行案内にします。

レビュー失敗時はRuleBasedの架空レビューへ置き換えません。固定解説と小テストは
モデルに依存せず利用可能であり、レビューだけを明示的に再試行できます。別クラウドへの
自動転送も行いません。

## 保存と上限

質問と表示済みヒントは、プロフィール・問題単位の会話ファイルへ保存します。
現在コード、生の診断、秘密情報は保存しません。履歴は直近20往復、40メッセージを
上限とし、問題単位で削除できます。

- 質問: 最大1,000文字
- LLMへ送るコード: 最大16KiB
- 表示する診断詳細: 最大4KiB
- 生成ヒント: 最大1,200文字

履歴上限により、プロンプト構築とJSON保存の時間・空間計算量を一定範囲に保ちます。

小テスト結果とコード改善レビューは `data/runtime/review_history/<profile_id>.sqlite3`
へ保存します。小テストは採点時点の全設問・選択・正解・解説、コードレビューは生成済みの
構造化テキスト、モデル、完了理由、生成日時を保存します。提出ソースとプロンプトは
保存しません。

両履歴は共通のプロフィール別論理上限1 GiBを使います。UTF-8 JSONエンベロープの合計が
80%に達するとUIで警告し、上限超過時は小テスト・レビューを区別せず最古から削除します。
画面取得は新しい順に20件単位、リポジトリAPIの最大ページサイズは100件です。

## UI方針

プロフィールとモデル選択は全タブ共通の上部ツールバーへ置きます。問題演習ページには、
問題文、コード、実行結果、安全化済み診断、会話型ヒント、解説をまとめます。
独立したヒントタブへ移動させず、実行結果を見ながら「わからない」または質問を送れる
配置にします。

生成要求は同時実行数1の専用キューへ入れ、同じボタンからの重複要求を受け付けません。
接続先、同意要否、RuleBasedへの退避は画面上で区別します。

質問欄のEnterは改行、Ctrl+Enter（macOSはCmd+Enter）は送信です。検証済み質問は
回答生成前にブラウザだけへ暫定表示し、回答が返った時点で質問・回答を一組として保存します。
生成中は単調時計による実測経過秒、完了後は実測所要時間を表示します。これはETAではなく、
将来の完了時刻を保証しません。

完了後のコードレビューも同じ実測表示と専用同時実行数1を使います。自動生成は、
その操作で全テストACになった場合、または初めてギブアップした場合だけ起動します。
既に完了済みの問題では「現在コードをAIレビュー」から明示的に再生成できます。
